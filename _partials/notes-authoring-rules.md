# Page authoring rules — READ THIS FULLY BEFORE WRITING ANY MARKUP

You are writing ONE page's body fragment for the First Perfumes Ind LLC website
(a UAE fragrance and cosmetics manufacturer, founded 2006, based in Jebel Ali, Dubai).

## 1. The output contract

Write **only** the page body fragment to `_content/<slug>.html`. Nothing else.

- **Do NOT** write `<!doctype>`, `<html>`, `<head>`, `<body>`, the header, the nav,
  the footer, or any `<script>` tag. `build.py` wraps your fragment in all of that.
- **Do NOT** write the breadcrumb hero. `build.py` generates it from `_content/pages.json`,
  so every page's breadcrumb is identical in structure. Your fragment starts at the
  *first content section after* the breadcrumb.
- **Do NOT** write `<style>` or `<script>` tags, or inline `style="..."` attributes.
  If you cannot achieve something with an existing class, choose a different component.
- Base indentation is **16 spaces** (the fragment sits inside `#smooth-content`).
  Match the indentation style of `_content/index.html`.

Your fragment is inserted verbatim between the generated breadcrumb and `<footer>`.

## 2. The one rule that matters most

**Only use class names that already exist in `css/style.css` or `css/site-fixes.css`.**

Before you write a class, grep for it:

```bash
grep -n '\.your-class-name[^a-zA-Z0-9_-]' css/style.css css/site-fixes.css
```

An invented class produces *unstyled markup on a production site*. This is the single
worst failure mode. `check.py` will fail the build on any undefined class, so an invented
class is not a shortcut — it is a guaranteed rework.

The same applies to nesting: most of this stylesheet is **ancestor-scoped**. A rule like
`.service-details-wrap .content h2 { }` only fires when `h2` is inside `.content` inside
`.service-details-wrap`. Copy the *whole* nesting chain from the notes, not just the leaf.

## 3. Which notes to read

Three catalogues exist. Read the sections relevant to your page — do not read all 3,900 lines.

| file | what is in it |
|---|---|
| `_partials/notes-components.md` | the 8 homepage section components + shared buttons and `.section-title` variants |
| `_partials/notes-inner-pages.md` | the ~21 inner-page CSS blocks the homepage never uses (service details, team, FAQ, contact form, blog list, pricing, careers, article body) |

## 4. Animation — use these, avoid those

**Safe on any page** (verified against `js/custom.js`):

| hook | usage |
|---|---|
| `.fade_anim` | `data-fade-from="top\|bottom\|left\|right"` (default `bottom`), `data-fade-offset` (40), `data-duration` (0.75), `data-delay` (0.15), `data-ease` (`power2.out`) |
| `.text-anim` | on headings only; no inner markup inside the element |
| `.counter` | inside `.single-countdown > .number`; **not** `.counter_number` (it has no CSS) |
| `.wow` + animate.css names | works, but prefer `.fade_anim` |
| `href="#section-id"` | in-page scroll — the handler was fixed to drive ScrollSmoother, so this now works |

**Do NOT use on a new page:**

- `.portfolioCard` / `.porfolio-card-wrapper` — the pin script is document-wide.
  At most **one** stack per page, and it must sit inside a `.porfolio-card-wrapper`.
- `.home1-process-section`, `.home3-process-section`, `.home4-banner-video`,
  `.home2-footer-top-section`, `.team-img-area` — pin/count machinery bound to the
  homepage's exact DOM tree. A partial copy silently does nothing or pins the wrong element.
- `.industries-wrap` / `.single-industries`, `.cursor-drag`, `.counter_number` — dead
  (JS handler exists, no CSS at all).
- `.magnetic-wrap` — generated by `custom.js`. Write `.magnetic-item` only.
- More than **one** Swiper per page. Check the collision table in the motion notes first.

Stagger `data-delay` across a row of cards (`.2`, `.3`, `.4`) — that is the pattern the
homepage uses and it is what makes the site feel considered rather than mechanical.

## 5. Content rules

- Copy is **dummy content the client will replace**, but it must be *plausible and specific*
  to fragrance manufacturing — never lorem ipsum, never `[placeholder]`, never "Lorem".
  Write as if for the real business: real-sounding process names, realistic numbers,
  UAE/Dubai/Jebel Ali context, ISO 22716, US FDA, EU CPNP, UK SCPN where relevant.
- Never invent a specific verifiable claim that could embarrass the client
  (no fake client names, no fake awards, no fake certifications beyond the five the
  homepage already shows, no invented staff names presented as real executives —
  for team members use plainly generic names and mark the section as placeholder copy
  in an HTML comment).
- Every heading level must nest properly. The `<h1>` is in the generated breadcrumb, so
  **your fragment must not contain an `<h1>`** — start at `<h2>`.

## 6. Images

- Use only files that exist in `images/`. Verify: `ls images/ | grep <name>`.
- Every `<img>` needs: a descriptive `alt`, `loading="lazy"`, `decoding="async"`.
  (The one exception is a hero image above the fold, which may use `fetchpriority="high"`
  and omit `loading="lazy"`.)
- Reuse is expected — this is placeholder imagery the client will swap. Prefer images whose
  subject matches the section; the asset notes group them by subject.

## 7. Spacing and structure

- Wrap each top-level section as `<div class="<component>-section mb-120">` and put its
  content inside `.container` (or `.container-fluid one` for full-bleed sections).
  Use `mb-60` for a tighter gap; the last section before the footer keeps `mb-120`.
- Use Bootstrap 5 grid classes (`row`, `col-lg-6`, `gy-4`) — they are available.
- Aim for **5–8 substantial sections** per page. A page with two thin sections does not
  read as premium. Vary the section types so consecutive pages do not feel identical.
